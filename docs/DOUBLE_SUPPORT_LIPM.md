## 모델과 보행 패턴

```text
왼발 SSP → DSP(왼발에서 오른발로 하중 이동)
→ 오른발 SSP → DSP(오른발에서 왼발로 하중 이동) → 반복
```

일정 높이 h, 점발, 각운동량 변화 무시의 LIPM이다. 상태 c, v는 수평 2차원 월드 좌표다.

```text
w = sqrt(g/h)
c_ddot = w^2 * (c - p)
```

SSP 동안 ZMP p는 지지발에 고정한다. DSP 동안 양발은 지면에서 고정하고, ZMP를 이전 지지발에서 새 지지발까지 선형으로 이동한다.

```text
alpha = DSP 경과 시간 / T_ds
p = (1-alpha)*p_old + alpha*p_new
```

`alpha`는 평면 점접촉 모델에서 새 발의 수직 하중 비율로 해석한다. 실제 접촉력 센서값이나 전신 동역학으로 계산한 힘은 아니다. DSP 경계에서는 한쪽 하중이 0이고 구간 내부에서 양쪽 하중이 양수다.

선형 ZMP 이동의 정확한 상태 전파:

```text
u = (p1-p0)/duration
C = cosh(w*duration), S = sinh(w*duration)
c1 = p1 + C*(c0-p0) + S/w*(v0-u)
v1 = u + w*S*(c0-p0) + C*(v0-u)
```

DSP 진입·종료에서 상태를 재설정하지 않아 CoM 위치·속도가 이어진다. DSP가 양수이면 ZMP도 연속이므로 이 모델의 CoM 가속도도 경계에서 연속이다. ZMP 속도는 경계에서 달라지므로 jerk 연속까지 보장하지 않는다.

발 수평 위치는 5차 smoothstep, 높이는 `64*clearance*s^3*(1-s)^3`로 구성했다. 이륙·착지 때 발 속도와 가속도가 0이 되며, DSP에서는 두 발을 고정한다.

## DSP를 반영한 착지점 계산

`xi=c+v/w`, 전체 스텝 시간 `T=T_ss+T_ds`로 정의한다.

```text
E = exp(w*T)
K = (exp(w*T_ds)-1)/(w*T_ds)    # T_ds=0이면 극한값 1
xi_next - p_new = E*(xi_start-p_old) - K*(p_new-p_old)
```

목표 전진 스텝 길이 `s=norm(v_cmd)*T`, 좌우 보폭 `width`에 대해 주기 XCoM 오프셋은 다음과 같다.

```text
b_forward = K*s/(E-1)
b_lateral = K*width/(E+1)
```

새 지지발이 왼발이면 다음 상대 XCoM의 횡방향 성분은 `-b_lateral`, 오른발이면 `+b_lateral`이다. 명령 방향으로 회전한 다음 상대 XCoM 목표를 `b_next`라 할 때:

```text
p_new = p_old + (E*(xi_start-p_old)-b_next)/K
```

따라서 기존 식의 시간만 바꾸는 대신 DSP 전달 계수 K까지 포함한다. `T_ds=0`에서는 기존 XCoM 착지점 식과 일치한다.

기본 초기 CoM 위치는 `[0, 0, 0.6]` m, 속도는 `[1, 0]` m/s로 원본과 동일하다. 주기 궤도 초기화는 `--periodic-start`로 선택할 때만 사용한다. 정지에서 출발하는 제어기는 아니다. 데모의 `create_model()`에서 `initial_position`, `initial_velocity`로 다른 초기 상태를 지정하거나, 기존처럼 `x_0`, `vx_0`, `y_0`, `vy_0`와 현재 상태를 직접 설정할 수 있다. 착지점 도달 가능성 제약은 없다.

## 시각화

기존 `demo_LIPM_3D_vt.py`와 동일한 2×2 배치, 위아래 높이 비율 2.5:1, 10×10 inch 창 크기를 사용한다.

| 위치 | 패널 | 표시 내용 |
|---|---|---|
| 왼쪽 위 | 3D 시뮬레이션 | 빨간 CoM, 파란 왼발, 자홍색 오른발, 초록 지면 투영 궤적. 기존과 같은 시점 `(20, -150)` |
| 왼쪽 아래 | 위에서 본 시뮬레이션 | CoM·양발 위치와 누적 궤적. 기존과 같은 CoM 추적 범위 및 동일 축척 |
| 오른쪽 위 | CoM 속도 | x는 검정, y는 보라. 실제값 실선, 목표값 점선 |
| 오른쪽 아래 | 보행 파라미터 | 전진 보폭 step length는 회색, 좌우 보폭 step width는 청록. 실제값 실선, 목표값 점선 |

네 번째 패널은 속도나 발 높이가 아니라, 착지한 양발 사이의 전진·횡방향 간격이다. 실제값은 착지 때 갱신하고 다음 착지까지 유지한다. 기본 주기 보행에서는 실제 보폭과 목표 보폭이 일치해 실선과 점선이 겹칠 수 있다.

추가 표시:

- 주황 별: 3D 및 평면도의 ZMP.
- 주황 궤적: 평면도의 ZMP 이동 기록.
- DSP의 주황 연결선: 두 점발 사이의 지지 선분.
- 속도·보폭 그래프의 옅은 주황 음영: 현재 재생 시점까지의 DSP 구간.
- 3D 제목: 현재 시간, SSP 지지발 또는 DSP 하중 전달 비율.

시뮬레이션을 먼저 계산한 뒤 기존 데모처럼 애니메이션으로 재생한다. 모든 곡선·목표선·궤적·음영은 현재 프레임까지만 표시되며 미래 데이터는 미리 그리지 않는다. 프레임 간격은 표시하는 시뮬레이션 시간에 맞춰 설정하지만 실제 GUI 재생 속도는 렌더링 성능에 영향을 받는다.

선으로 그린 다리는 시각화용이며 관절 기구학이나 길이 제약을 구현하지 않는다.

## 후속 범위

현재 모델에는 발·다리 질량, 충격, 마찰 제약, 발 면적, 관절 및 착지 도달 범위, 전신 토크 제약이 없다. DSP 추가를 통한 실제 안정성 평가는 이러한 제약이나 전신 시뮬레이션에서 별도 확인해야 한다. 다음 질량 스위칭 모델은 이 SSP/DSP 구조와 상태 전파를 기반으로 확장할 수 있다.


## 기존 코드와의 구조 대응

기존 `LIPM_3D.py`와 두 기존 데모 파일은 수정하지 않고 새 파일만 정리했다.

| 기존 이름·역할 | 새 코드 |
|---|---|
| `LIPM3D.__init__()` | `LIPM3DDoubleSupport.__init__(dt, T, T_ds, s_d, w_d, support_leg)` |
| `initializeModel()` | CoM 높이·양발 위치·지지발 프레임 초기화. 양발 위치는 각각 보존 |
| `x_0`, `y_0`, `vx_0`, `vy_0` | SSP 시작 상태 |
| `x_t`, `y_t`, `vx_t`, `vy_t` | 현재 상태. 위치는 기존과 같은 지지발 상대 좌표 |
| `COM_pos`, `left_foot_pos`, `right_foot_pos` | 월드 좌표. 현재 CoM은 매 step 갱신 |
| `step()` | CoM·ZMP 상태만 한 dt 전파. 발 이동과 위상 전환 시점 결정은 데모에서 수행 |
| `calculateXfVf()` | SSP 종료 시점 상태 예측 |
| `calculateFootLocationForNextStepXcoMWorld()` | DSP 전달 계수를 포함한 다음 착지점 계산 |
| `switchSupportLeg()` | 월드 CoM 위치·속도를 유지하며 다음 지지발 프레임으로 전환 |
| `Ball`, `Line`, `LIPM_3D_Animate` | 기존처럼 별도 시각화 클래스. 축은 인자로 전달 |
| `ani_3D_*`, `ani_2D_*` | 3D·평면도 초기화와 프레임 갱신 |
| `COM_vel_2D_*`, `step_params_2D_*` | 속도·보폭 그래프 초기화와 프레임 갱신 |
| `_init_func()`, `_update_func()` | 네 패널의 콜백을 결합해 하나의 애니메이션으로 재생 |

DSP 때문에 추가한 것은 `T_ds`, `phase`, `beginDoubleSupport()`, 이동 ZMP 전파 함수다. `T`는 SSP 시간, `T_d=T+T_ds`는 전체 스텝 시간이다. DSP 동안에는 이전 지지발 기준 좌표를 유지하고, DSP 종료 후 `switchSupportLeg()`에서 좌표를 전환한다. 위 수식의 c는 월드 CoM이며 코드의 `x_t`, `y_t` 자체와는 구분한다.

데모는 기존 흐름을 따라 `create_model()`에서 초기화하고, `calculateSwingFootTrajectory()`에서 스윙 궤적을 준비한 뒤 `simulate()`의 루프에서 다음 순서를 실행한다.

```text
CoM step → 스윙발 위치 갱신 → SSP 종료 시 DSP 시작
→ DSP 종료 시 지지발 전환 → 다음 착지점 및 스윙 궤적 계산 → 데이터 기록
```

CLI와 화면 없는 검증을 유지하기 위해 실행부는 `main()`에 두고, 패널 콜백은 그 내부에 두었다. import할 때 시뮬레이션이나 창이 자동 실행되지는 않는다.

리팩터링 확인: 기본/DSP=0/대각선/초기 속도 교란의 4개 조건에서 모든 저장 상태를 이전 궤적과 비교했다. 최대 차이는 약 `7.5e-14`이며, 기존 세 파일의 SHA-256 해시가 모두 유지됐다. 수치 검증 5개도 통과했다.

## 원본과 동일한 초기 상태 및 명령 스케줄

| 항목 | 새 데모 기본값 | 원본과의 관계 |
|---|---|---|
| CoM 위치 | `[0, 0, 0.6]` m | 동일 |
| CoM 속도 | `[1, 0]` m/s | 동일 |
| 왼발 위치 | `[-0.2, 0.3, 0]` m | 동일 |
| 오른발 위치 | `[-0.2, -0.3, 0]` m | 원본 데모에 명시된 값. 원본 클래스의 양발 위치 덮어쓰기 오류는 재현하지 않음 |
| 초기 지지발 | 왼발 | 동일 |
| 첫 계획의 전진 보폭 | 0.6 m | 동일 |
| 속도 명령 | 네 구간 모두 `[1, 0]` m/s | 동일 |
| 발너비 명령 | `[0.4, 0.8, 0.4, 0.4]` m | 동일 |
| 명령 전환 | 10·20·30스텝 종료 후 다음 스텝 계획부터 | 동일 |
| dt / 실행 시간 | 0.02초 / 10초 | 동일. 새 데모는 t=0 및 마지막 시점도 기록 |
| 발 높이 | 최대 0.1 m | 최대값 동일. 새 데모의 부드러운 이륙·착지 궤적은 유지 |

초기 상대 CoM 위치는 `(x_0, y_0)=(0.2, -0.3)` m이며 주기 보행 상태가 아니다. 첫 계획 보폭도 0.6 m로 별도 지정되어 있으므로 초기 속도가 증가한 뒤 주기 운동으로 수렴하는 과도응답이 나타난다. 초기 스파이크를 없애려고 상태를 재설정하거나 속도를 제한하지 않는다.

첫 스텝 이후 전진 보폭은 `norm(v_cmd)*(T_ss+T_ds)`로 갱신한다. 원본은 DSP가 없으므로 `norm(v_cmd)*T_ss`이다. DSP를 포함해 같은 평균 속도를 의미하도록 한 차이이며, DSP=0이면 원본과 같다.

기본 DSP 설정에서 발너비 변경 시점은 4.2초(10스텝), 8.4초(20스텝), 12.6초(30스텝)다. 기본 10초 실행에서는 30스텝에 도달하지 않으며, 마지막 값은 이전 값과 같은 0.4 m다. 실제 보폭과 목표값은 매 기록 시점에 별도로 저장해 그래프가 명령 변화를 표시한다. 실제 보폭은 지지발 전환 시 최근 두 지지발 위치로 갱신한다.

원본과 직접 비교하려면:

```powershell
.\.venv\Scripts\python.exe .\LIPM\demos\demo_LIPM_3D_double_support.py --ds 0
```

위 조건에서 원본의 499개 CoM 위치·속도 샘플과 비교한 최대 절대 오차는 약 `1.2e-13`이었다. 양발 스윙 궤적이나 기록 시점의 위상 라벨까지 동일하다는 의미는 아니다. 원본 세 파일의 해시는 유지됐다.

고정 발너비와 주기 초기화가 필요한 별도 비교는 다음처럼 명시한다.

```powershell
.\.venv\Scripts\python.exe .\LIPM\demos\demo_LIPM_3D_double_support.py --periodic-start --width 0.3 --vx 0.5
```
