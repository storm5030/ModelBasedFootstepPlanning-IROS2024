# 연구실 로봇 RL 코드에 질량 스위칭 모델 이식하기

## 목적과 현재 판단

질량 스위칭 모델을 연구실 로봇용 별도 코드에 적용할 때 필요한 사항을 정리한다. 현재는 기존 더블 서포트 데모와 비교해 발 위치·CoM 궤적 차이가 크지 않아 이식을 보류한다. 목적은 우선 동작 차이를 이해하는 것이며 성능 개선을 전제하지 않는다. 대상 코드는 아직 검토하지 않았고, 이 문서는 설계·점검 항목이다.

이번 범위는 질량점 정의, 상태 추정, 모델 전환, 착지점 계산 및 정책 연결이다. DSP 구간 구성·시간 관리·접촉 보상 설계는 다루지 않는다. 해당 내용은 DOUBLE_SUPPORT_RL_PORTING.md를 참고한다. 기존 대상 코드의 지지 상태 전환 신호가 제공된다고 가정한다.

## 1. 먼저 확정할 질량의 경계

몸통 질량 mb는 트렁크 링크만이 아니라 양발을 제외한 전체 로봇 질량이다. 팔·골반·허벅지·종아리 등이 포함된다. 발 질량 mf는 제외할 발 링크 집합의 합이다.

대상 URDF나 시뮬레이터에서 발목 모터·기어·발바닥이 어느 링크에 속하는지 확인한다. 실제 링크 구분을 무시하고 데모의 40/10 kg을 그대로 적용하지 않는다. 다리 전체를 발 질량으로 제외하는 것도 현재 모델과 다르다.

좌우 발 질량이 같은 것이 현재 데모의 가정이다. 좌우 비대칭 질량의 가중평균 위치는 계산할 수 있지만, 대칭 조건으로 유도된 주기 오프셋과 초기화 공식을 그대로 사용하면 안 된다. 첫 이식은 대칭 근사로 할지 실제 비대칭 모델로 확장할지 명시한다.

## 2. 네 질량점을 별도 상태로 유지

| 이름 | 포함 링크 | 용도 |
|---|---|---|
| 전체 CoM | 로봇 전체 | 기존 상태 추정·전체 운동 평가 |
| 몸통 CoM | 양발 제외 | 유효 CoM 계산의 기준 |
| 왼발 포함 유효 CoM | 몸통 + 왼발 | 오른발이 지지발일 때 선택 |
| 오른발 포함 유효 CoM | 몸통 + 오른발 | 왼발이 지지발일 때 선택 |

대칭 발 질량에서 a = mf/(mb+mf)라고 두면 다음과 같다.

c_eff,L = (1-a)*c_body + a*c_foot,L
c_eff,R = (1-a)*c_body + a*c_foot,R
c_total = (mb*c_body + mf*c_foot,L + mf*c_foot,R)/(mb+2mf)

유효 CoM은 몸통과 포함한 발의 질량중심을 잇는 선분 위에 있다. 지지발을 제외하는 부분계 모델이므로 실제 로봇 전체 CoM과 다르다. 질량 자체나 실제 로봇 링크를 물리적으로 켜고 끄는 기능이 아니다.

중요한 위치 구분:
- 발의 질량중심: 위 가중평균에 사용.
- 발 접촉 기준점/CoP/ZMP: 진자의 지지 기준과 착지 계획에 사용.
- 발 링크 원점: 위 두 위치와 다를 수 있음.
- 루트/트렁크 위치: 양발 제외 CoM과도 일반적으로 다름.

현재 데모는 발 점질량을 발 위치에 놓는 단순화다. 실제 코드에서는 링크의 inertial origin 및 회전을 적용한 세계 좌표 질량중심을 사용한다. 시뮬레이터 API가 링크 원점 상태를 주는지 질량중심 상태를 주는지 먼저 확인한다.

## 3. 속도와 좌표계

질량이 일정하면 속도도 같은 질량 비율로 계산한다.

v_eff = (1-a)*v_body + a*v_foot.

발 질량중심 속도와 몸통 CoM 속도를 사용한다. 회전하는 링크의 원점 속도만 제공될 경우 v_com = v_origin + omega_link × r_world로 오프셋을 반영한다. 모든 위치·속도는 동일 좌표계와 동일 시각이어야 한다.

전체 CoM 상태만 사용할 수 있다면 대칭 질량 기준으로 다음과 같이 역산할 수 있다.

c_body = ((mb+2mf)*c_total - mf*(c_foot,L+c_foot,R))/mb
v_body = ((mb+2mf)*v_total - mf*(v_foot,L+v_foot,R))/mb

이는 입력 전체 CoM이 실제 질량 가중평균이고 질량·발 상태 정의가 일치할 때만 성립한다. 루트 상태를 전체 CoM이라고 간주해 대입하지 않는다. 가능한 경우 링크별 질량중심 상태에서 직접 집계한다.

질량 랜덤화가 있으면 사용 중인 질량이 명목값인지 환경별 실제값인지 명확히 한다. 실제 질량을 알고 쓰는 시뮬레이션과 명목 질량만 쓰는 로봇 제어를 구분해 평가한다.

## 4. 고정 계획 높이와 실제 높이를 분리

실제 몸통·발·유효 CoM의 높이는 로봇 운동에 따라 변한다. 기존 모델을 유지하려면 계획용 높이 h_plan을 전환 경계에서 정하고 해당 모델 구간 동안 유지한다. omega = sqrt(g/h_plan)를 사용한다. 높이는 정한 지지면 기준이어야 한다.

데모처럼 발 질량중심 높이를 0으로 가정하지 말고 실제 발 inertial 위치를 확인한다. 실제 유효 높이와 고정 계획 높이 차이를 로그에 남긴다. 높이 변화가 큰 경우 이 근사로 충분한지 별도 판단한다.

기존 두 데모의 --height 의미:
- 몸통 기준 버전: 몸통 높이가 입력값.
- total-CoM 기준 버전: 전체 CoM 초기 높이가 입력값이고 몸통 높이를 역산.

평지 점발 가정의 40/10 kg에서:
- 몸통 높이 0.6 m → 유효 계획 높이 0.48 m, 전체 CoM 초기 높이 0.4 m.
- 전체 CoM 초기 높이 0.6 m → 몸통 높이 0.9 m, 유효 계획 높이 0.72 m.

실제 로봇에서 데모의 0.9 m를 그대로 강제하지 않는다. 로봇 자세와 도달 가능한 전체 CoM 높이를 기준으로 설정한다. 전체 CoM과 몸통 CoM 높이를 모두 임의의 상수로 독립 지정하면 질량 관계와 모순될 수 있다.

## 5. 전환은 물리 상태 변경이 아니라 모델 좌표 변경

기존 지지 전환 이벤트를 받아 포함할 발을 선택한다. 순간 접촉 불리언의 흔들림만으로 모델을 반복 전환하지 않는다.

전환 시:
1. 실제 링크·몸통 상태는 그대로 유지한다.
2. 새 포함 발로 유효 CoM 위치·속도를 재계산한다.
3. 계획 높이와 omega 및 지지 기준의 상대 상태를 갱신한다.
4. 새로운 상태에 맞춰 다음 착지 목표를 계산한다.

몸통 상태가 동일하고 대칭 질량이면 전환에 따른 차이는 다음과 같다.

delta c_eff = a*(c_new_foot-c_old_foot)
delta v_eff = a*(v_new_foot-v_old_foot)

이 점프는 정의한 부분계가 바뀌어서 생기는 좌표 변화다. 이를 실제 몸통 순간이동이나 충격 가속도로 처리하지 않는다. 실제 접촉 충격은 물리 엔진이나 센서 상태에 별도로 반영된다.

새/이전 유효 CoM 위치 차분을 그대로 속도로 사용하면 가짜 큰 속도가 생긴다. 질량 가중 속도를 사용하고, 필터나 미분기의 상태도 어느 모델에 속하는지 구분한다. 현재 데모의 착지점 예측은 발의 종료 속도 0을 가정하므로 실제 발 미끄러짐·잔류 속도가 크면 예측 전환식과 상태 재계산의 차이를 검토한다.

## 6. 착지점 계산에 반영할 것

입력은 선택된 유효 CoM 위치·속도, 계획 높이, 지지 기준점, 목표 보폭·폭과 보행 시간이다. omega만 바꾸고 기존 전체 CoM의 ICP나 기존 목표 오프셋을 혼용하면 안 된다.

ICP_eff = c_eff,xy + v_eff,xy/omega.

유효 질량점 전환을 포함한 예측과 목표 ICP 오프셋을 한 쌍으로 사용한다. 이미 구현한 calculateDesiredDCMOffset()과 calculateFootLocationForNextStepXcoMWorld()의 관계를 유지한다. 목표 오프셋은 다음 착지점을 계획할 때마다 계산하며, 현재 조건의 보정식과 가정은 MASS_SWITCH_OFFSET.md에 정리되어 있다. 이 문서에서는 지지 구간 구성 자체를 변경하지 않는다.

현재 오프셋은 대칭 발 질량·일정 높이·평지·발 종료 속도 0의 가정을 포함한다. 비대칭·단차·가변 시간으로 확장할 때는 다시 유도·검증한다.

대상 코드가 Torch 병렬 환경이면 질량 비율, 후보 유효 CoM, 높이, 오프셋을 환경별 텐서로 구현한다. 데모의 NumPy 객체나 두 스텝 고정점 계산을 매 정책 틱에 실행하지 않는다.

## 7. 데모와 실제 제어의 경계

데모는 유효 CoM을 전파한 뒤 스윙발 상태에서 몸통 위치·속도를 역산한다. 실제 환경에는 물리 시뮬레이션으로 결정된 몸통 상태가 있으므로 이 역산 결과로 실제 로봇 상태를 덮어쓰면 안 된다.

실제 제어에서의 기본 흐름:
실제 링크 상태 → 몸통·발 질량중심 집계 → 선택된 유효 CoM → 착지점 플래너 → 기존 정책 → 기존 관절 제어.

기존 전체 CoM 기반 관측을 일괄적으로 유효 CoM으로 치환하지 않는다. 플래너 입력만 바꾸는 최소 이식부터 비교하고, 정책이 필요로 할 때 후보점·선택 모델·계획 높이를 별도 관측으로 추가한다.

기존 속도·높이 보상이 루트, 몸통 또는 전체 CoM 중 무엇을 평가하는지 명시한다. 플래너의 유효 CoM을 보상 기준으로 자동 대체하지 않는다. 유효 CoM의 스위칭 점프를 자세·속도 불연속 페널티로 처리하지 않는다. 관측 의미나 차원을 바꾸면 정책 재학습/파인튜닝과 체크포인트 호환성을 검토한다.

## 8. 차이가 작은 이유를 확인하는 비교 방법

보정된 오프셋은 일정 명령에서 기존과 같은 보폭·발너비·주기 평균 속도를 만들도록 설계되어 있다. 따라서 정상 주기 상태의 착지 위치가 비슷하다는 것만으로 질량 스위칭 효과가 없다고 결론 내릴 수 없다. 반대로 내부 유효 CoM이 달라졌다는 것만으로 물리적 동작 차이가 입증되는 것도 아니다.

다음 비교를 분리한다.
- 동일한 실제 몸통·발 위치/속도에서 두 플래너가 내는 첫 착지 목표 차이.
- 같은 정책·환경에 각 플래너를 넣었을 때 실제 몸통·전체 CoM 궤적 차이.
- 각 모델의 periodic-start에서 얻는 정상 주기 궤적 차이.

모델별 periodic-start는 초기 위치·속도 자체가 달라질 수 있으므로 동일 초기조건 실험과 섞지 않는다. 몸통 높이 0.6 m와 전체 CoM 초기 높이 0.6 m 실험도 구분한다.

조건: 속도 명령, 전체 스텝 시간, 목표 폭, 실제 초기 상태, 정책, 지형 및 난수 시드를 가능한 한 동일하게 유지한다. 발 질량 변경은 모델 파라미터만 바꾸는 실험과 물리 로봇 질량도 바꾸는 실험을 분리한다.

차이 평가:
- 목표 착지점의 x/y 차이와 실제 착지 오차
- 동일 정의의 CoM 궤적 차이, 속도 진폭·최대/최소 및 위상
- 모델 전환 전후 유효 CoM/ICP 변화
- 질량 비율과 명령 전환·외란에 따른 목표 차이

## 9. 단계별 검증과 로그

1. 발 질량 0이면 기존 플래너와 일치하는지 검사한다.
2. 링크 질량 집계와 네 CoM의 가중평균 관계를 검증한다.
3. 원점과 질량중심의 속도 변환 및 좌표계 회전을 검사한다.
4. 전환 시 실제 몸통 상태가 보존되고 유효 상태만 정의에 맞게 바뀌는지 검사한다.
5. 계획 높이가 구간 내 일정하며 지지면 기준으로 양수인지 검사한다.
6. 보정한 목표 오프셋으로 말단 ICP, 보폭·발너비·주기 평균 속도가 맞는지 검사한다.
7. 동일한 실제 상태를 입력한 기준/스위칭 플래너의 목표 차이를 기록한다.
8. 이후에 정책 재학습/파인튜닝 및 물리 시뮬레이션 비교를 진행한다.

필수 로그:
- 사용한 질량과 질량 비율, 명목/실제 질량 구분
- 전체 CoM, 몸통 CoM, 양발 질량중심의 위치·속도
- 두 후보 유효 CoM과 선택된 모델
- 고정 계획 높이, 실제 유효 높이, omega
- 지지 기준점, 유효 ICP, 목표 오프셋, 목표/실제 착지점
- 전환 이벤트와 전환 전후 실제/모델 상태

현재 검증은 제안한 축약 모델의 내부 일관성에 관한 것이다. 지지발을 제외한 부분계가 표준 전체 CoM LIPM과 같은 물리식을 따른다는 엄밀한 유도는 별개이며, 이식을 곧바로 물리적 타당성 검증으로 간주하지 않는다.
